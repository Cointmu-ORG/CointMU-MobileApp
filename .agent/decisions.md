# Decisions

Format: ID, decision, reason. Add a new entry (never silently rewrite) when something changes.

Note: D-11 and D-17 are intentionally unused (the history-source topic is tracked as Q-11).

## Decided

- **D-01 Expo managed + TypeScript strict.** Dev on Linux/Windows without a Mac, Expo Go for fast testing, EAS Build for release.
- **D-02 Expo Router.** Industry default for Expo. Routes in root `app/`, thin re-exports.
- **D-03 FSD adapted.** FSD layers in `src/`, root `app/` reserved for routes to avoid the Expo Router name clash.
- **D-04 ethers v6.** Already used in desktop (TypeScript), logic can be reused. Needs `react-native-get-random-values`.
- **D-05 Zustand.** Same as desktop. Persist only non-sensitive state.
- **D-06 NativeWind v4.** Tailwind in React Native, works in Expo Go.
- **D-07 i18next, JSON per language (`id`, `en`).** Same approach as desktop.
- **D-08 No monorepo.** Blockchain code from desktop is copied manually, then adapted (remove Node/Electron APIs).
- **D-09 HTTP polling, no WebSocket.** Simpler and more robust on mobile networks.
- **D-10 Non-custodial, single account in MVP.** Data model keeps `accountIndex` for later multi-account.
- **D-12 BIP-44 `m/44'/60'/0'/0/0`, 12-word mnemonic.** Industry standard for EVM wallets, compatible with MetaMask-style import.
- **D-13 Import via mnemonic and private key.**
- **D-14 Backup flow.** Show mnemonic once, block screenshots, require 3-word verification quiz.
- **D-15 PIN (6 digits, hashed) + optional biometrics.** Required at app open, after auto-lock, before each signature, and before revealing the mnemonic.
- **D-16 Auto-lock 1 min default (configurable). 10 failed PINs offers reset.**
- **D-18 Light theme only (white/blue) for MVP.** Matches desktop.
- **D-19 No fiat conversion.** Coin units only. Use `N/A` if a price field appears.
- **D-20 Linter: Steiger + ESLint boundaries.** Fails CI on FSD violations.
- **D-21 Testing: Jest + RNTL, E2E (Maestro) after MVP.**
- **D-22 Fee mode detected at runtime.** EIP-1559 if `getFeeData()` gives `maxFeePerGas`, else legacy `gasPrice`.
- **D-23 Finality default `FINAL_CONFIRMATIONS = 12`.** Show "confirmed" at 1. Tune once block time and hashrate are known.
- **D-24 `.agent/` docs are referenced from `CLAUDE.md`** (Claude Code does not auto-read `.agent/`).
- **D-25 App name: Muvo.** Display name "Muvo", tagline suggestion: "Muvo, dompet CointMU". Name is invented (Mu from CointMU, "vo" read as move/value/vault). Identifiers: slug `muvo`, scheme `muvo`, bundle ID / package name `com.cointmu.muvo` (iOS and Android). The bundle ID is permanent after the first store release; do not change it. Display name can be changed anytime. TODO before first publish: check availability on Play Store, App Store, and domain/social handles, and check for existing trademarks named "Muvo" (e.g. Creative MUVO speakers).
- **D-26 Expo Router root pinned to `./app`.** `["expo-router", { "root": "./app" }]` in app.json. Expo Router can treat `src/app` as the routes root, which clashes with the FSD `app` layer (D-03). Pinning makes root `app/` the only routes folder.
- **D-27 PIN lockout state lives in SecureStore.** Failed-attempt count, lockout-until and lastSeenAt are stored in SecureStore (`muvo.auth.lockout`), not in a persisted Zustand store. AsyncStorage is unencrypted and easier to tamper with; next to the PIN record the counter gets the same protection and is wiped together with it. If the device clock goes backwards (`now < lastSeenAt`) while a lockout is running, the lockout restarts from now. Moving the clock forward still ends a lockout early; only a server clock could prevent that.
- **D-28 Private-key imports show a mandatory "back up your key" warning.** A private-key wallet has no mnemonic and the key is stored only in the device keychain, so the user must tick an acknowledgement before importing.
- **D-29 Local tx records store the nonce.** Needed to detect replaced or dropped transactions. The nonce is fetched with `getTransactionCount(addr, 'pending')`.
- **D-30 Mobile uses Tailwind v3; desktop tokens are copied.** NativeWind v4 requires Tailwind v3 while the desktop app is on Tailwind v4 (`@theme`). Token values from the desktop `index.css` are copied into `src/shared/ui/theme/colors.json`, which both `tailwind.config.js` and code that needs raw colors read. Desktop names Inter but does not bundle it, so mobile uses the system font (no `expo-font`).
- **D-31 Steiger `fsd/insignificant-slice` is off.** The architecture defines slices that have a single consumer by design in the MVP (each feature, `entities/account`). Revisit once the slice set settles. All other recommended Steiger rules stay on.
- **D-32 New mnemonic is written to SecureStore right away, with wallet status `pendingBackup`.** Create flow: `none` → `pendingBackup` (phrase in SecureStore) → quiz passed → `pendingPin` → PIN set → `active`. Import flow: `none` → `pendingPin` → `active`. If the app is killed mid-onboarding, the router resumes at the step for the stored status. The wallet is only `active` after the quiz (create) and the PIN are done.
- **D-33 Fresh-install wipe for iOS reinstalls.** The iOS Keychain survives uninstall but AsyncStorage does not. On startup, if the `muvo.installed` marker is missing from AsyncStorage, the wallet secret, PIN record and lockout state are deleted from SecureStore before anything reads them, then the marker is set. This must ship in the first public release; adding it later would wipe existing users' keys.
- **D-34 PIN stored as a versioned record.** SecureStore holds `{ v, algo, iterations, salt, hash }`, not just a hash. Verification uses the record's own params; after a successful unlock, a record whose params differ from the current config is rehashed. The KDF itself is still a placeholder (Q-32).
- **D-35 Committed `CLAUDE.md` imports `AGENTS.md`.** Supersedes D-24: rules are referenced from `AGENTS.md`, and a committed `CLAUDE.md` containing `@AGENTS.md` makes Claude Code load them. Machine-specific notes (graphify, Obsidian vault paths) move to the gitignored `CLAUDE.local.md`.
- **D-36 Auth guard uses Expo Router protected routes.** Root and onboarding layouts wrap screens in `Stack.Protected`, driven by wallet status and session state, with `redirectTo` computed by one function (`resolveEntryRoute`). Protected screens never render, and a status change redirects automatically. There is no root `app/index.tsx`: the home tab (`(tabs)/index`) owns `/`.
- **D-37 Icons are imported per file.** Use `lucide-react-native/icons/<name>` instead of the package barrel. The barrel pulls in about 2,000 icon modules (Metro does not tree-shake by default) and made Jest runs take minutes.
- **D-38 Android auto-backup is off (`android.allowBackup: false`).** Auto-backup would restore AsyncStorage (wallet status and the D-33 install marker) on a new device or reinstall, but never the Android Keystore keys that encrypt SecureStore. The app would then skip the reinstall wipe and treat the wallet as active with a secret it cannot decrypt. Users move wallets between devices with their mnemonic or private key.
- **D-39 Startup integrity check with a recovery screen.** After hydration, if the persisted status promises data that SecureStore no longer has (`pendingBackup`/`pendingPin` without a readable secret, or `active` without a readable secret or PIN record), the app does not go to the lock screen. It wipes local wallet data (same as reset) and shows `/recover`, which explains the data couldn't be read and offers import by mnemonic or private key (reusing import-wallet), plus "create a new wallet instead" so users without a backup are not stuck. The flag is persisted, so a killed app returns to the recovery screen. The check reads the secret once to validate its shape; the value never leaves the wallet entity. Replaces the earlier known limit where a missing PIN record only led to the reset offer after 10 failed attempts.
- **D-40 Versioning: one release version in three files; EAS owns build numbers.** `scripts/bump-version.js <bump-type> <codename>` (ported from the desktop app, same CLI) wraps `npm version`: it sets the version in `package.json` and `package-lock.json` (root fields, written by npm so the lockfile stays valid), and the `version` hook (`scripts/sync-release-files.js`) sets `app.json` `expo.version` and stamps `package.json` `"codename"`. It then commits `chore: release version <version>-<codename>`, tags `v<version>` and pushes both to `main`, and refuses versions that are not semver or not newer than the current one. `expo.version` drops any prerelease suffix because iOS `CFBundleShortVersionString` takes integers only, so `1.2.0-beta.1` ships as `1.2.0`. Native build numbers (`ios.buildNumber`, `android.versionCode`) are not in app.json and the script never touches them: EAS remote versioning (`cli.appVersionSource: "remote"` with `autoIncrement`) will own them once EAS builds are set up (Q-31). Expo recommends remote versioning, and under it the local build numbers are ignored. The app version lives in static `app.json`; if a dynamic `app.config.*` is added, the script refuses to run until it is updated.
- **D-41 PIN KDF v2: PBKDF2-SHA256 with 2,000 iterations (was 20,000).** Measured first: PIN setup already hashed once, after the confirmation matched (no hash on the first entry, no double hash, no derivation running at the same time); the cost was that single hash. Pure-JS PBKDF2 runs on the JS thread, and Hermes has no JIT: in an interpreter (V8 `--jitless`, i7-8750H) one hash took 4,676 ms at 20,000 iterations and 466 ms at 2,000, paid at setup and on every unlock, with the UI frozen. A dev bundle is slower still (lazily compiled, unoptimized bytecode). The lower count costs little real security: the record sits in the keychain (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`) behind the lockout, and an attacker who extracts it can try all 10^6 PINs on a GPU in seconds at either count. Records are versioned (D-34): v1 records still verify with their own params and are rehashed to v2 after the next successful unlock. Setup now hashes after a painted frame with a UI-thread spinner. A native KDF (Q-32, Q-30) would allow a much higher cost.
- **D-42 Splash: native splash held through bootstrap, then a JS hand-off.** `expo-splash-screen` (config plugin) shows the desktop logo (`resources/icon.png` from the desktop app) at 120 dp on the `surface` token background (`#f8fafc`; a test keeps app.json in step with the token). `preventAutoHideAsync()` runs at module scope; the root layout renders nothing until bootstrap is done (install marker, hydration, integrity check, stored language), so no unstyled screen shows. Then a JS copy of the splash sits over the laid-out app, the native splash is hidden, and the copy fades and zooms out over 350 ms; under reduce motion it is removed at once. Expo Go shows the app icon instead of the config-plugin splash, so the splash can only be checked in a development or release build.
- **D-43 RPC node choice: preset list plus one custom node, chain-checked.** `EXPO_PUBLIC_RPC_URLS` (comma-separated, replaces `EXPO_PUBLIC_RPC_URL`) holds the preset nodes; source code never names one. In Settings > Network the user picks a node or adds one http(s) URL of their own. Selecting or adding a node first calls `eth_chainId` (one try, 5 s timeout) and refuses any answer other than 1912, or no answer; the current node stays in use. Each row shows reachable with latency, unreachable or wrong chain. The selected and custom URLs persist in AsyncStorage (`muvo.network`, not secret); a stored choice that no longer exists falls back to the first preset. Changing node clears and refetches the balance. Plain http:// works only where the platform allows cleartext (dev builds).
- **D-44 Several accounts from one recovery phrase (supersedes D-10).** "Add account" derives the next BIP-44 index (`m/44'/60'/0'/0/{n}`) from the stored mnemonic and switches to it; the phrase is read only for the derivation and dropped. Settings > Accounts and the account chip on Home switch accounts; each account can get a local name (max 24 characters, empty means "Account N"). Switching clears the balance so the previous account's balance never shows. Private-key wallets cannot add accounts; the screen explains why. The wallet store persists `accounts` (version 1; a v0 store migrates its single address into the list). Several separate wallets with different secrets are not supported (Q-34).
- **D-45 "Log out" is two items: Lock now and Remove wallet from this device.** A non-custodial wallet has no account to sign out of. "Lock now" locks the session immediately (nothing is deleted). "Remove wallet from this device" reuses reset-wallet behind a strong warning, a "I have my recovery phrase or private key" acknowledgement (first confirmation), the PIN (PIN only, counts toward the lockout) and a final confirmation, then wipes keys and local data and returns to onboarding.
- **D-46 Settings tab mirrors the desktop settings, minus mining.** Order: General (language), Accounts, Network, Security (change PIN, biometrics, auto-lock, recovery phrase), Log out, About (version and build, chain ID, current RPC node, documentation, GitHub, report an issue, MIT license). Desktop wording is reused where it exists. Skipped as desktop-only or out of scope: appearance (light only, D-18), notifications, mining, connected sites, external sources, advanced, privacy and diagnostics (Q-28), export keystore, reveal private key (Q-35), hardware wallets, ask-password-to-send (mobile always asks before signing), clipboard clearing (no secret is ever copied), software updates (stores handle them), reset to defaults. The language choice is persisted and restored at bootstrap; the auto-lock timeout is a persisted auth preference (immediately, 1, 5, 15 min). The build number comes from `expo-application`; Expo Go and dev clients report their own, so About shows "development" there.
- **D-47 Node probe (2026-11-07): the three CointMU nodes support EIP-1559; finality stays at 12.** `npm run probe:nodes` (`scripts/probe-nodes.js`, read-only JSON-RPC, Node built-ins only) checked the preset nodes 10.64.24.101/106/113:8585. All report chain 1912 (net_version 1912), Geth 1.10.26, 5 peers, and the same block hash at height 374017. The latest block has `baseFeePerGas` (7 wei) and `eth_feeHistory` works, so EIP-1559 is active; this closes Q-03, and runtime detection (D-22) stays as the guard. Over the last 1000 blocks: average block time 12.54 s, p95 38 s, max 109 s, uncle rate 0.2 %. 12 confirmations is about 2.5 minutes and the low uncle rate gives no reason to change D-23 (feeds Q-04). `eth_getLogs` accepted a 10,000-block range (10–76 ms), a full block took 5–8 ms and a 100-block batch 18–36 ms on the LAN. `eth_getTransactionReceipt` returns `null` for an unknown hash. `txpool` and `debug` are off. The chain is quiet: none of the last 1000 blocks held a transaction. The nodes are plain HTTP and LAN/ZeroTier only, so they are the dev presets in `.env.example`; release still needs HTTPS (Q-02).
- **D-48 Tx status uses only standard eth_ reads; polling values come from the probe.** `resolveTxStatus` (`entities/transaction/lib`) is a pure function of one observation: `eth_getTransactionCount(from, 'latest')` (read first, so a tx mined in between still shows its receipt), `eth_getTransactionReceipt`, `eth_getTransactionByHash` and `eth_blockNumber`. Receipt: status 0 is `failed`, otherwise `confirmed` until `FINAL_CONFIRMATIONS` (12), then `final`. No receipt and the node knows the tx: `pending` (also after a reorg removes the receipt). Unknown tx with its nonce used: `replaced`. Unknown tx with its nonce unused: `pending`, then `dropped` after 3 minutes (longer than the 109 s worst block gap). No txpool or debug API is used (off on the nodes). Config in `entities/transaction/config` cites the probe date: receipt poll every 6.27 s (half the block time, floor 3 s), getLogs chunk 10,000 blocks, native scan page 1,000 blocks inside a 50,000-block (~7 day) window. `scripts/watch-tx.js` runs the same TS state machine (loaded with Node's type stripping) against a live node.
- **D-49 Native CMU has 18 decimals (closes Q-01).** Wei is protocol-level in geth, so the native coin always has 18 decimals. `NATIVE_ASSET.decimals` is 18 and no longer marked as an assumption.
- **D-50 Receive QR encodes the plain checksummed address.** No EIP-681 URI: every wallet and scanner reads a bare address, and the sender chooses the asset and amount. The screen shows the account name, copies only the address (still the only clipboard write in the app) and shares it through React Native's Share API, with a note to send only CMU or CointMU tokens.
- **D-51 Amount input is locale-aware and float-free.** `parseAmountInput` accepts the locale's decimal separator (id: comma, en: dot). The other separator is accepted too when it is the only one, because decimal keypads differ by platform (Android often shows a dot in any language). Thousands separators are not accepted: two separators are invalid rather than guessed. More fraction digits than the asset's decimals is an error, never rounded. "Max" fills the field with `formatAmountInput`, which round-trips through the parser.
- **D-52 Dropped needs the node to forget the tx for a full window (refines D-48).** D-48 counted the 3-minute window from `createdAt`, so a long-pending tx that briefly went unknown (a node switch) could drop at once. Now a record stores `unknownSince`: `dropped` needs `eth_getTransactionByHash` to return null, the stored nonce to be unused (`latest` ≤ nonce), and both to have held for `droppedAfterMs` since it first went unknown. A tx the node still returns stays pending however long. A used nonce without our receipt is `replaced`, even if this node still holds our tx in its pool. A tx in a block whose receipt is not indexed yet stays pending.
- **D-53 Send flow.** `/send` is a nested stack: form → review → result. The form validates the checksum and the amount and quotes the fee (`estimateGas` fails early on a revert). Review refetches the fee on open and before signing if older than 30 s, shows from, to (in full), amount, max fee, total and node, warns (never blocks) on a self-send or a contract recipient, and checks the balance including the fee (a token send needs CMU for gas). Authentication (PIN or biometrics) comes right before signing; only then is the secret read. `eth_chainId` must be 1912 on the selected node, the nonce is `pending`, the signer is built and dropped inside `signWithSecret`, and the tx is broadcast once with no retry. The pending record is saved before navigation. A broadcast that times out may still have reached the node, so it is saved as "uncertain" and the poller settles it (dropped if the node never got it) instead of inviting a second send. The result screen has no back button or swipe-back. RPC errors map to friendly copy; raw node messages never reach the UI. Explorer links appear only when the optional `EXPO_PUBLIC_EXPLORER_URL` is set (Q-27).
- **D-54 History: three sources behind `TransactionSource`, merged by hash.** Local records (live status), a native block scan (1,000 full blocks per page, 50,000-block window of about 7 days, 50 blocks in flight so ethers batches them) and ERC-20 `Transfer` logs for the listed tokens (10,000-block ranges, halved down to 500 when the node answers with an error, not when it is unreachable). Values come from the probe (D-47). The native scan shows only top-level txs with a value; zero-value calls from the owner (token transfers) come from the logs. Cursors are cached in memory per account and chain and pages load lazily; after a restart the scan starts again from the head, while local records are persisted. Limits: internal transfers are invisible (Q-33), and an outgoing token transfer that reverted and was not sent from this app does not appear (no log).
- **D-55 Tokens: built-in list plus custom tokens per chain.** `BUILTIN_TOKENS` ships empty until the owner names official tokens. Users add a token by contract address: `getCode` must be non-empty, `symbol` and `decimals` must decode (ABI string or bytes32 symbol; `name` optional; control characters stripped, lengths capped), and an "unverified token" warning is shown before it is saved. Custom tokens persist per chain ID in `muvo.tokens` (public data) and are wiped with the wallet; built-in ones can be hidden, custom ones removed. Balances use `balanceOf`, four calls at a time, poll with the native balance and clear on account or node change. A scanned request for a token that is not in the list is refused (its decimals are unknown).
- **D-56 Scan: a pure parser, prefill only.** Accepts a plain address, EIP-681 native requests (`ethereum:[pay-]<addr>[@<chainId>][?value=<wei>]`, exponent notation included) and ERC-20 transfers (`ethereum:<token>[@<chainId>]/transfer?address=<to>&uint256=<amount>`). Another chain ID, a bad checksum, an ENS name, a non-integer amount or another function is refused with a clear message. Text that looks like a secret (a 64-hex string, or 12/24 words that are all BIP-39 words) is refused first with a warning and is never logged or kept. A scan never sends; it fills the Send form (from Home it opens Send, from Send it goes back). The camera runs only while the screen is focused, takes the first code until the user scans again, and the config plugin requests the camera only (no microphone or audio).
- **D-57 Jest suites were flaky from one-time work inside the first test; fixed at the cause.** The first test of a suite paid one-time costs against the 5 s timeout: `renderRouter('./app')` requires every route module lazily during the first render (1–2 s alone), the accounts test ran a real PBKDF2 derivation, and the quiz test slept 700 ms of real time. With a cold transform cache and the default cores − 1 workers (11 on a 12-thread, 8 GB machine), memory ran low (a cold run was killed) and CPU contention multiplied those costs past 5 s at random. Fixes: router suites load the route modules at file load (`jest.preload-routes.ts`); the accounts UI test stubs the derivation (covered by `wallet-lib.test.ts`); the quiz uses fake timers; Jest runs on half the cores and recycles a worker above 700 MB (`jest.config.js`). Verified: three parallel and three `--runInBand` full runs green, plus a cold-cache run with at least 1.5 GB free throughout. No timeout was raised and no test was skipped.
- **D-58 Transaction status poller.** An app-level hook polls every unsettled local record (all accounts) at `TX_POLL_INTERVAL_MS` while the app is in the foreground, resumes every unfinished record on start (records are persisted), backs off by doubling up to 60 s after failed polls, and never runs two polls at once. Status badges carry an icon and text for every state (confirmed shows n/12), in the home activity list, the history list and the tx detail screen, in en and id.
- **D-59 One PIN layout (`PinEntry`) for every PIN screen.** Device feedback: the lock screen had the keypad at the bottom while the send confirm screen had it right under the dots, because that screen sits in a scroll view where `flex-1` collapsed. `shared/ui/PinEntry` is now the only PIN layout (optional logo, title, subtitle, dots, status line, keypad anchored to the bottom); `PinPrompt` and `NewPinForm` render it, and `FormScreen` content grows to the screen height so the layout is the same inside a scroll screen. Keys are `clamp(min(23 % of the width, 11 % of the height), 72, 88)` dp with a digit font of 40 % of the key; the height cap keeps four rows on a 375×667 screen below a native header.
- **D-60 Send screens live in the root stack; one header style, icon-only back (refines D-53).** The first screen of a nested stack has no back button, so the Send form had none. `send/index`, `send/review` and `send/result` are now root-stack screens (no `send/_layout`). Every sub-screen header comes from `SUB_SCREEN_HEADER`: translated centered title, `headerBackButtonDisplayMode: 'minimal'`, and `(tabs)` has a translated `title`, so iOS can never show a route group name as the back label. Import and verify in onboarding get a back button. Without back on purpose: tabs, lock, create (auto-advances), backup and set-pin (first screen of their status), recover, and the send result (Done goes home; Android back does the same). While a transfer is signed and broadcast, the review screen hides back, disables the swipe and ignores Android back. "Edit and try again" pops to the existing form instead of pushing a second one.
- **D-61 History loading states.** First load: skeleton rows in the list area. Pull to refresh: the `RefreshControl` only. Older pages: a centered spinner in the list footer. The shared `Spinner` rotated a wrapper that could stretch to its parent's width, which made the ring orbit the middle of the row; the rotating view is now exactly the ring.
- **D-62 Account switcher is a form sheet (refines D-44).** The home account chip opens `/account-switcher` with `presentation: 'formSheet'` (detents 0.5 and 1, grabber, 24 dp corners; no new dependency). It lists accounts (name, short address, a checkmark and the loaded balance on the active one; other accounts' balances are never fetched), switches and closes on tap, and has "Add account" and "Manage accounts" rows; Manage opens the existing accounts page (rename), which stays in Settings. Private-key wallets show the same explanation as before. Android renders no native header inside a form sheet, so the title is part of the content.

## Open questions (need an answer from the owner)

- **Q-01 Decimals of CMU.** Closed by D-49: 18 (wei is protocol-level in geth). Was: assumed 18.
- **Q-02 RPC reachability.** `10.64.24.101:8585` is a private LAN address. A phone outside that network cannot reach it. Need a public HTTPS endpoint (VPS + reverse proxy) or a VPN for dev. Also plain HTTP is blocked by default on Android release builds and iOS ATS, so production needs HTTPS (or an explicit cleartext exception for dev only).
- **Q-03 EIP-1559 support.** Closed by D-47: supported (baseFeePerGas present, eth_feeHistory works). Was: Unknown. Check `londonBlock` in genesis or call `eth_feeHistory`. D-22 covers both cases meanwhile.
- **Q-04 Finality.** Measured in D-47: 12.54 s average block, 0.2 % uncle rate; 12 kept. Still open for a long-run reorg check. Confirm block time and reorg risk to set `FINAL_CONFIRMATIONS`.
- **Q-11 History source.** Desktop has an in-app explorer, so check how it reads data. Pure-RPC history for native transfers means scanning blocks, which is heavy. Decide between bounded scan (current plan) or a small indexer/explorer API.
- **Q-26 "Multi coin" meaning.** More ERC-20 tokens on CointMU only, or other chains too? Current design supports tokens on one chain, with chain config isolated so multi-chain can be added.
- **Q-27 Block explorer URL** for tx links on mobile. Desktop has it built-in, so there may be no public URL. The app reads an optional `EXPO_PUBLIC_EXPLORER_URL` (D-53) and shows links only when it is set; a public URL is still needed.
- **Q-28 Sentry.** Keep it on mobile? If yes, define scrubbing rules before enabling.
- **Q-29 App name checks (D-25).** Before first publish: check "Muvo" availability on Play Store, App Store, domain and social handles, and run a trademark check (including Creative MUVO).
- **Q-30 Mnemonic derivation performance.** ethers v6 runs BIP-39 PBKDF2 in pure JS, which is slow on Hermes. Derivation is behind one function (`entities/wallet/lib/derive.ts`). Options: (A) register a native pbkdf2 (e.g. react-native-quick-crypto; new dependency, needs a dev build), (B) also store the derived index-0 private key in SecureStore for signing and keep the mnemonic only for reveal. Undecided.
- **Q-31 When to move from Expo Go to a development build.** Needed for Sentry, iOS Face ID, and any native crypto.
- **Q-32 PIN KDF algorithm and parameters.** A 6-digit PIN has only 10^6 values, so the KDF must be slow. Current placeholder: PBKDF2-SHA256, 20,000 iterations, 16-byte salt (`entities/auth/config`). Tune on a real device; D-34 makes changing it safe.
- **Q-33 Native history via block scan cannot see internal transfers.** Value moved by contract calls (internal transactions) does not appear as a transaction to the user's address. Adds weight to Q-11.
- **Q-34 Several separate wallets.** D-44 adds accounts from one secret. Holding more than one secret (e.g. a phrase wallet and an imported key side by side) needs per-wallet SecureStore keys, a wallet switcher and per-wallet reset. Out of scope for now; decide if users ask for it.
- **Q-35 Reveal private key.** The desktop has "Reveal private key". Mobile shows no key for private-key wallets (and none for phrase wallets), so a private-key wallet cannot be backed up from the app. Decide whether to add a PIN-gated, screenshot-blocked key reveal.
- **Q-36 Speed up or cancel a pending transaction.** Out of scope for the wallet core. A stuck tx can only be waited out or, once dropped, sent again. Adding it means re-signing the same nonce with a higher fee (or a 0-value self-send for cancel), with the same auth and chain checks, and tracking the replacement in history.
